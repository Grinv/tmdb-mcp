# Privacy Policy

`tmdb-mcp` is a local [Model Context Protocol](https://modelcontextprotocol.io)
server: it runs as a process on your own machine (via `npx` or a local clone),
speaking stdio to your MCP client (Claude Desktop, Claude Code, etc.). It has
no server component of its own, no telemetry, and no analytics — this policy
covers exactly what it does with data, in full, because there isn't more to
say beyond it.

## Data collection

`tmdb-mcp` collects no data of its own. It has no database, no accounts, and
sends nothing to its maintainer or to any analytics/telemetry service.

The only inputs it handles are:

- **Credentials you supply**, via environment variables in your MCP client's
  own config (e.g. `claude_desktop_config.json`): `TMDB_API_TOKEN` (required),
  `OMDB_API_KEY` (optional), plus non-secret preferences `TMDB_LANGUAGE`/
  `TMDB_REGION`. These stay in your client's local config file; `tmdb-mcp`
  never transmits them anywhere except as described below.
- **Tool call arguments**, generated by the AI model you're using (e.g. a
  movie title, a person's name, a TMDB/IMDb id) as it calls one of this
  server's tools on your behalf.

## Usage and third-party sharing

Each tool call results in an outbound HTTPS request to exactly one of two
third-party APIs, carrying only what that specific call needs:

- **TMDB** (`api.themoviedb.org`) — `TMDB_API_TOKEN` as an `Authorization:
Bearer` header, plus the search/lookup parameters the tool call supplies.
  Used for essentially every tool. Governed by
  [TMDB's own Privacy Policy](https://www.themoviedb.org/privacy-policy) and
  [API Terms of Use](https://www.themoviedb.org/api-terms-of-use) once your
  request reaches them.
- **OMDb** (`omdbapi.com`) — `OMDB_API_KEY` as an `apikey` query parameter,
  plus an IMDb id or title/year. Only reached when `OMDB_API_KEY` is set and
  a ratings-enrichment path is used (`get_movie`/`get_tv`'s ratings, or the
  standalone `get_ratings`). OMDb doesn't publish a page dedicated solely to
  privacy; its combined [Terms/legal page](https://www.omdbapi.com/legal.htm)
  governs your request once it reaches them.

`tmdb-mcp` sends data to no other destination — no analytics vendor, no
logging service, no server operated by its maintainer.

## Storage and retention

- **Caching**: successful API responses are cached in the server process's
  own memory only (never written to disk), for a short configurable TTL
  (`CACHE_TTL_MS`, default 5 minutes) to cut latency and avoid hammering
  TMDB/OMDb. The cache is cleared entirely when the process exits and is
  never shared across machines or users.
- **Logging**: operational logs go to stderr only (never a file, never a
  remote endpoint), with credentials stripped before anything is written.
  Log verbosity is controlled by `LOG_LEVEL` (default `info`); logs live only
  as long as your MCP client keeps that stderr stream around.
- Beyond the cache TTL and the running process's lifetime, `tmdb-mcp` retains
  nothing. There is no persistent storage layer of any kind.
